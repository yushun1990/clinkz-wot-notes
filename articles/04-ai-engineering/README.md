# 人与 AI 的工程协作

本系列记录 ClinkZ-WoT 如何使用仓库治理、连续状态、架构 owner、work package
和独立证据来维持长期 AI 开发。

## 核心问题

- 为什么聊天记录不能成为项目记忆；
- Owner 和 AI 如何划分责任；
- AGENTS、PLAN、PROJECT_STATE、docs 和 workspace 如何避免互相覆盖；
- 如何让问题从讨论迁移到正式规范；
- 如何按风险调整审查深度；
- 如何通过纵向 architecture slice 验证模块能否组合。

## 写作边界

本系列不是宣传“一键 AI 编程”。应同时呈现：

- AI 带来的推进能力；
- 上下文丢失、过度设计和错误自信；
- 仓库治理的成本；
- Owner 必须理解并质疑关键设计的责任。
